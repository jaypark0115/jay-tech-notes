2. 위치 오차를 네 방향 스파이크로 바꾸는 RTL

output-layer는 세 모듈로 구성된다. error_encoder가 signed x/y 오차를 네 개의 양수 방향 자극으로 분리하고, 네 개의 lif_neuron이 막전위를 갱신한다. controller_top은 이 네 spike를 X/Y pull·push 모터 출력으로 연결한다.

원문 코드 controller_top.v · error_encoder.v · lif_neuron.v

2.1 먼저 모듈 사이의 계약을 단순하게 만들었다

signed position → direction magnitude → membrane update → motor spike
모듈입력출력책임
error_encodersigned x, y4방향 magnitude오차의 부호와 크기 분리
lif_neuron방향 자극, 속도 크기spike누적·누설·임계값·리셋
controller_top위치, 속도 크기모터 4방향동일 뉴런 4개 생성과 배선

2.2 signed 오차를 네 개의 단방향 신호로 분리했다

중심을 0으로 보면 현재 위치의 반대 방향이 복귀 방향이므로 ex=-x, ey=-y로 오차를 만든다. 각 축에서 양수와 음수는 동시에 활성화되지 않는다. 결과적으로 뒤의 LIF 뉴런은 signed 방향 판단을 다시 하지 않고 0 이상의 자극 크기만 처리할 수 있다.

error_encoder.v - 방향별 오차 분리 
wire signed [W_IN-1:0] ex = -x;
wire signed [W_IN-1:0] ey = -y;

assign X_x_pull = (ex > 0) ? (ALPHA * ex) : 0;
assign X_x_push = (ex < 0) ? (ALPHA * (-ex)) : 0;
assign X_y_pull = (ey > 0) ? (ALPHA * ey) : 0;
assign X_y_push = (ey < 0) ? (ALPHA * (-ey)) : 0;

이 분리는 단순하지만 중요한 설계 선택이다. 한 축의 반대 방향 actuator가 동시에 켜지는 상태를 encoder 단계에서 제거하고, 네 출력 채널의 의미를 고정하기 때문이다.

2.3 막전위는 누적되고, 누설되며, 임계값에서 spike를 낸다

U는 뉴런의 막전위 상태다. 매 clock마다 이전 전위에서 LEAK를 빼고, 방향 자극 X_in을 더한다. 속도 크기 v_abs는 K_V와 곱해 감쇠 항으로 들어간다. 임계값을 넘은 상태에서는 spike를 내고 U_THR만큼 빼는 subtractive reset을 사용한다.

lif_neuron.v - 상태 갱신과 발화 
spike <= (U > U_THR);

if (U < LEAK) begin
  U <= 0;
end else begin
  U <= U - LEAK
       + (W_GAIN * X_in)
       - ((U > U_THR) ? U_THR : 0)
       - (K_V * v_abs);
end

LEAK

입력이 사라졌을 때 상태가 계속 남지 않도록 매 cycle 감소시키는 항이다.

U_THR

막전위가 이 값을 넘으면 방향 제어용 spike가 발생한다.

W_GAIN

위치 오차가 막전위에 얼마나 크게 반영되는지 정한다.

K_V

속도 크기가 클 때 추가 발화를 억제하는 감쇠 항이다.

2.4 generate로 네 방향 뉴런을 같은 구조로 통합했다

top에서는 encoder 출력과 속도 입력을 같은 index 규칙으로 묶는다. 0/1은 X축 pull/push, 2/3은 Y축 pull/push다. generate loop로 네 개의 LIF 인스턴스를 만들기 때문에 방향마다 코드가 달라지는 문제를 줄이고, 같은 파라미터를 일관되게 적용할 수 있다.

controller_top.v - 4채널 LIF 생성과 모터 출력 
for (i = 0; i < 4; i = i + 1) begin : SNN_CHANNEL
  lif_neuron #(.WU(W_POS), .WX(W_POS)) u_lif (
    .clk(clk), .rstn(rstn),
    .X_in(X_in[i]),
    .v_abs(v_abs[i]),
    .spike(spikes[i])
  );
end

assign motor_X_PULL = spikes[0];
assign motor_X_PUSH = spikes[1];
assign motor_Y_PULL = spikes[2];
assign motor_Y_PUSH = spikes[3];

2.5 코드에서 확인되는 한계도 함께 남긴다

  • 현재 파라미터는 방향별로 동일하며 공의 동역학에 맞춘 자동 학습 과정은 포함하지 않는다.
  • W_POS 폭 안에서 곱셈과 상태 갱신이 이뤄지므로 overflow·saturation 정책을 더 명확히 할 수 있다.
  • spike가 곧바로 모터 출력에 연결되므로 실제 actuator를 위한 pulse width, dead-zone, 상호 배타 제어가 별도로 필요하다.
  • 따라서 이 코드는 전체 기계 제어기가 아니라 SNN 기반 방향 출력 계층의 RTL 근거로 해석해야 한다.
