SNN 기반 BallControl 제어 회로

이 경진대회는 스파이킹 뉴럴 네트워크를 조사하는 1차 과제와, 그 원리를 공의 위치 제어 문제에 적용하는 2차 과제로 진행됐다. 2차 BallControl의 목표는 30×30cm 보드 위에 임의로 놓인 1~30g 공을 보드 중앙의 반경 1cm 영역으로 이동시키는 것이었다. 프로젝트에서는 공의 위치와 무게를 디지털 spike 입력으로 바꾸고, LIF 뉴런이 시간에 따라 누적한 상태로 +X·−X·+Y·−Y 네 방향의 제어 이벤트를 만들었다. 아래에서는 과제의 물리 조건이 어떤 회로 사양으로 바뀌었는지, 실제 Verilog가 담당한 범위가 어디까지인지, 시뮬레이션과 합성 결과를 어떻게 해석해야 하는지를 한 흐름으로 설명한다.

프로젝트 개요

최종 발표에서 사용한 실험망은 99개 위치 입력, 32개 은닉 뉴런, 4개 방향 출력 뉴런으로 구성된다. 현재 위치는 11×9 격자 중 하나를 활성화하는 one-hot 벡터로 표현하고, 무게는 일정한 시간 창 안에서 발생하는 spike 수로 표현한다. 네 출력 뉴런의 발화 횟수는 X축과 Y축의 양·음 방향 제어량으로 해석한다. 이 구조는 공의 동역학을 직접 계산하는 물리 시뮬레이터가 아니라, 센서가 제공했다고 가정한 상태를 모터 방향 이벤트로 바꾸는 디지털 제어 파이프라인이다.

경진대회에서 구현한 것

이 프로젝트를 이해하려면 네트워크 규모보다 먼저 입출력 경계를 보는 편이 정확하다. 입력은 카메라 영상이나 압력 센서의 원신호가 아니라 이미 숫자로 변환된 공의 위치와 무게이다. 출력도 모터 전압이나 PWM 파형이 아니라 네 방향의 1-bit spike이다. 구현의 중심은 이 두 경계 사이에서 위치 오차를 방향별로 나누고, 시간에 따라 막전위를 갱신하며, 방향별 발화량을 얻는 SNN 제어 회로이다.

따라서 이 글에서 말하는 “BallControl 구현”은 센서, 모터 드라이버, 기구부를 포함한 완성 장치 전체를 뜻하지 않는다. 직접 확인된 코드는 error_encoder → 4채널 lif_neuron → motor direction output 경로이며, 최종 발표에는 이 출력 계층을 포함한 99→32→4 실험망의 시뮬레이션과 합성 결과가 제시돼 있다. 두 자료의 범위를 구분해 읽어야 코드와 발표 결과를 과장 없이 연결할 수 있다.

1차 SNN 조사에서 2차 제어 회로로

경진대회의 1차 과제는 스파이킹 뉴럴 네트워크의 기본 원리와 하드웨어 구현 사례를 조사하는 단계였다. LIF 뉴런의 막전위 갱신, 시간 다중화 방식, spike 부호화와 같은 개념을 정리한 뒤, 2차 BallControl 과제에서는 그 개념을 실제 제어 신호 생성 문제에 적용했다. 따라서 이 프로젝트의 핵심은 학습 모델의 정확도 경쟁이 아니라, 연속적인 물리 상태를 유한한 비트와 클록으로 표현하고 그 결과를 모터 방향 신호에 대응시키는 회로 설계에 있다.

검증Verilog 시뮬레이션, 합성, Vivado 전력 추정기능과 구현 가능성을 회로 수준에서 확인

일반적인 인공신경망이 한 번의 행렬 연산으로 출력을 계산하는 것과 달리, SNN은 여러 시간 단계에 걸쳐 들어오는 spike와 뉴런 내부 상태를 함께 사용한다. LIF 뉴런은 입력이 들어올 때마다 막전위를 누적하고, 시간이 지나면 일부를 누설하며, 임계값을 넘으면 spike를 발생시킨다. 이 특성은 위치 오차가 계속 존재할 때 반복적인 방향 이벤트를 만들고, 오차가 작아질수록 이벤트를 줄이는 제어 표현으로 해석할 수 있다. 다만 이러한 가능성이 실제 기구부의 안정성을 자동으로 보장하는 것은 아니며, 기계 시스템에는 별도의 센서 피드백과 동역학 검증이 필요하다.

설계는 한 번에 전체 네트워크를 완성하는 방식으로 진행되지 않았다. 먼저 LIF 뉴런의 막전위 갱신과 흥분·억제 연결을 조사하고, 위치만 한 번 전달하는 one-shot 입력으로 방향 연결을 점검했다. 이후 같은 위치에서도 공의 무게에 따라 필요한 반응량이 달라진다는 조건을 반영하기 위해 입력을 rate encoding으로 확장했다. 마지막으로 대표 위치와 15g·30g 조건의 spike 수, 합성 자원, 전력 추정값을 정리했다. 개념 조사에서 시작해 최소 기능 확인, 입력 모델 확장, 구현 보고서 확인으로 이어진 개발 흐름이다.

시스템 구성

위치와 무게는 서로 다른 입력 속성을 가진다. 위치는 활성화된 좌표를 나타내며, 무게는 시간축의 spike 발생 빈도를 조절한다. 전체 경로는 입력 표현, 계층별 상태 계산, 방향별 출력 해석으로 구성된다. 좌표는 X축 −5부터 +5까지의 11개 값과 Y축 −4부터 +4까지의 9개 값을 조합해 99개 위치로 이산화했다. 실제 보드의 연속 좌표를 그대로 쓰지 않고 격자 하나를 하나의 입력 뉴런에 대응시킨 이유는 현재 위치가 회로 내부에서 모호하지 않게 표현되도록 하기 위해서다.

01 · 입력 표현 X·Y 위치와 공의 무게 보드 좌표와 15g·30g 조건
02 · 위치 부호화 11×9 one-hot 99개 중 현재 좌표 하나를 활성화
03 · 상태 계산 32개 LIF 뉴런 흥분·억제 가중치와 막전위 갱신
04 · 방향 출력 4개 LIF 뉴런 +X · −X · +Y · −Y
05 · 출력 해석 방향별 spike count 모터가 반응할 방향과 크기로 변환

99→32→4 구조는 최종 발표의 네트워크 기준이다. 저장소의 Verilog 세 파일은 전체 실험망이 아닌 네 방향 출력 제어 인터페이스를 다루는 참고 모듈이다.

99개 입력의 값은 32개 은닉 뉴런으로 전달되고, 은닉층의 spike는 네 개 출력 뉴런에 연결된다. 출력 채널은 양의 X축과 음의 X축, 양의 Y축과 음의 Y축을 각각 담당한다. 예를 들어 공이 오른쪽에 있어 중심으로 이동하려면 음의 X축 채널이 활성화되어야 한다. 시뮬레이션에서는 채널별 spike 수를 이동 단계로 해석했지만, 실제 시스템에서는 spike를 모터의 회전 방향, 구동 시간 또는 PWM 명령으로 바꾸는 후단 회로가 추가되어야 한다.

구현 범위와 검증 경계

발표자료 기준 구조

99→32→4 SNN과 시간 단계 제어

위치 one-hot 입력, 32개 은닉 뉴런, 4개 방향 출력, spike count decoding과 실행 FSM을 포함한다. 실험망은 100개의 시간 단계를 진행하며 각 단계의 입력 spike, 막전위, 출력 spike를 계산한다.

참고 RTL 모듈

오차 분리와 4채널 LIF 출력

error_encoder, lif_neuron, controller_top은 signed X·Y 오차가 네 방향 1-bit 이벤트가 되는 경로를 보여준다. 이 세 파일은 최종 제출 전체를 재현하는 독립 빌드가 아니라 출력층 제어 원리를 설명하는 공개 스냅샷이다.

기능 시뮬레이션

무게에 따른 rate encoding 변화

15g와 30g을 서로 다른 digital weight로 바꾸고, 다섯 개 초기 위치별 spike 수와 위치 변화를 기록한다. 첫 실험의 one-shot 입력과 두 번째 실험의 rate encoding은 뉴런 임계값과 누설 계수도 다르므로, 결과 차이를 무게 입력 하나의 효과로만 해석하지 않는다.

검증 대상 외 항목

물리 센서·모터 폐루프

카메라 위치 추정, 실제 모터 구동 파형, 기구부 응답과 중앙 반경 1cm 도달 여부를 연결한 보드 실험 자료는 포함하지 않는다.

해석 경계: 발표자료의 이동 경로는 SNN/제어 모델의 시뮬레이션 결과이다. 실제 공이 보드 위에서 같은 경로로 움직였다는 물리 실험 결과는 포함하지 않는다.

이 구분은 결과를 축소하기 위한 것이 아니라 증거 수준을 명확히 하기 위한 것이다. 확보된 자료는 SNN 구조, 모듈 간 신호, 시뮬레이션 결과, 합성 보고서와 전력 추정치를 설명할 수 있다. 반면 카메라가 공의 위치를 읽는 과정, 모터 드라이버의 전기적 인터페이스, 보드의 기울기와 공의 마찰을 포함한 폐루프 동작은 별도의 실험 자료가 필요하다.

담당 범위

팀 프로젝트에서 확인되는 기여는 문제 조건을 회로 사양으로 바꾸는 과정, SNN과 LIF 구조 조사, 입력·뉴런·출력 모듈의 통합, 시뮬레이션 결과 정리와 발표 자료 구성이다. 공개된 모듈의 존재만으로 특정 파일 전체를 한 사람이 단독 작성했다고 단정하지 않으며, 팀 결과와 개인의 기여 범위를 구분한다.

합성 표에는 LUT 10개, FF 41개, DSP와 BRAM 0개가 기재된다. I/O는 83개로 별도 집계되며 사용률은 99.85%이다. 전력 2.302W는 보드 실측이 아닌 Vivado 추정값이며, I/O 항목은 1.968W를 차지한다. 수치는 작은 내부 로직과 넓은 top-level 인터페이스의 특성을 나타낸다.

기능 시뮬레이션에서는 15g과 30g 조건을 각각 다섯 개 초기 위치에 적용했다. 일부 조건은 중앙 좌표에 도달했지만, 무거운 공을 나타낸 조건에서는 목표를 지나치거나 중심 근처에서 한 축이 남는 결과도 나타났다. 이는 무게를 더 높은 spike 빈도로 바꾸는 것만으로 정밀 제어가 완성되지 않음을 보여준다. 실제 폐루프 제어로 확장하려면 현재 위치를 매 제어 주기마다 다시 측정하고, 출력 spike를 모터 구동량으로 변환한 뒤, overshoot와 진동을 기준으로 임계값·누설·가중치를 재조정해야 한다.
