2. 입력 spike가 네 방향 제어 이벤트가 되는 회로

SNN은 입력이 들어온 순간의 값만 계산하지 않습니다. 각 뉴런이 막전위를 상태로 보관하고, 입력 spike와 가중치를 누적하며, 누설과 임계값 판정을 반복합니다. 이 프로젝트에서는 그 시간축 계산을 FSM으로 제어하고, 마지막 네 출력 뉴런의 spike를 X·Y 방향 신호로 해석했습니다.

전체 구조와 선별 코드의 관계

최종 발표의 실험 네트워크는 99→32→4 구조입니다. 저장소에 공개한 세 Verilog 파일은 signed 위치 오차를 네 방향으로 나누고 LIF 출력에 연결하는 경로를 읽기 쉽게 선별한 코드입니다. 두 자료는 같은 프로젝트의 SNN 제어 개념을 보여주지만, 서로 같은 top module이나 동일한 합성 실행 파일이라고 보지는 않습니다.

뉴런
LIF: 누적 · 누설 · 임계값 · reset
시간
100 time steps
출력
방향별 spike count와 X/Y decoding
코드
error_encoder · lif_neuron · controller_top

LIF 뉴런은 입력을 누적하고 조금씩 잊습니다

발표자료의 Baby Neuron datapath는 입력 spike에 해당하는 가중치를 더하고, 현재 막전위에 누설을 적용한 뒤, 임계값을 넘으면 출력 spike를 만들고 상태를 초기화하는 흐름입니다. 누설은 나눗셈기 대신 오른쪽 shift를 사용해 하드웨어 비용을 줄였습니다.

입력 pre-synaptic spike 현재 time step의 활성 입력
가중합 Σ(weight × spike) 흥분은 더하고 억제는 뺌
누설 U − (U >> k) 시간이 지나면 막전위 감소
판정 U ≥ threshold 임계값을 넘으면 spike
상태 reset 또는 다음 U 다음 클록을 위한 레지스터

FSM이 한 time step 안의 계산 순서를 고정합니다

여러 뉴런이 같은 입력과 상태를 읽기 때문에 계산 순서가 흔들리면 시뮬레이션과 합성 결과를 비교하기 어렵습니다. 최종 발표자료는 초기화, 입력 처리, 누적 계산, 결과 산출과 표시를 상태로 나누고 100개의 time step을 순서대로 진행합니다.

IDLE / INIT 상태와 counter 초기화 새 위치 입력 준비
RUN_INPUT 입력 spike 생성 one-hot 또는 rate encoding
RUN_ACCUM 뉴런 상태 갱신 가중합·누설·발화
CALC_DONE 방향별 spike 집계 X/Y 제어량 계산
DISPLAY 결과 유지 다음 입력 전까지 출력 확인

이 구조의 목적은 한 사이클 안에 모든 뉴런을 동시에 계산한다고 과장하는 것이 아니라, 시간 단계별 입력과 상태 갱신의 경계를 분명히 만드는 것입니다.

99개 위치 입력을 32개 상태와 4개 방향으로 압축합니다

입력 계층의 99개 뉴런은 보드 위치를 나타내고, 32개 은닉 뉴런은 위치별 흥분·억제 연결을 시간에 따라 통합합니다. 출력 계층은 제어에 필요한 네 방향만 남깁니다. 마지막 단계에서는 서로 반대인 방향의 spike 수를 비교해 X축과 Y축의 순 제어량을 얻습니다.

계층크기받는 정보내보내는 정보
입력9911×9 one-hot 위치와 rate 입력위치별 spike
은닉32흥분·억제 가중합시간축 상태와 spike
출력4은닉 계층 spike+X · −X · +Y · −Y
decoder2축방향별 spike countX/Y 제어량과 완료 상태

보관된 Verilog에서는 네 방향 출력 경로를 확인할 수 있습니다

error_encoder는 signed X·Y 값을 부호에 따라 네 개의 양수 크기로 분리합니다. controller_top은 같은 lif_neuron을 네 번 배치하고 각 spike를 방향 신호에 연결합니다. 이 코드는 전체 99→32→4 실험망을 재현하는 실행 패키지가 아니라, 출력 계층의 인터페이스와 상태 갱신을 설명하는 참고 코드입니다.

입력 signed X · Y 중앙 기준 위치 오차
error_encoder 네 방향 magnitude 부호와 절댓값 분리
lif_neuron × 4 막전위와 spike 클록 동기 상태 갱신
controller_top X/Y pull · push 방향별 1-bit 이벤트
error_encoder.v lif_neuron.v controller_top.v

공개 코드는 프로젝트 구조를 설명하기 위해 남긴 세 모듈입니다. 전체 네트워크의 가중치 파일, 테스트 데이터와 Vivado 프로젝트는 저장소에 포함하지 않았습니다.

이 회로에서 중요했던 판단

상태와 인터페이스

뉴런 모델과 모터 신호는 같은 것이 아닙니다

출력 spike는 제어 의도를 나타내는 이벤트입니다. 실제 모터의 PWM, pulse width와 기구부 응답은 별도 변환 계층이 필요합니다.

검증 가능성

time step 경계를 먼저 고정해야 합니다

입력 생성, 막전위 갱신과 출력 집계의 순서를 FSM으로 나누면 파형에서 최초 오차가 발생한 지점을 추적하기 쉬워집니다.
