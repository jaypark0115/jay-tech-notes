1. YOLOv2를 정수 연산으로 바꾸기

학습된 YOLOv2는 부동소수점으로 계산하지만, FPGA에서는 메모리 사용량과 연산 자원을 줄이기 위해 정수 연산을 사용했습니다. 단순히 소수점을 없애는 작업은 아닙니다. 각 layer가 가진 값의 범위를 조사하고, 정수로 바꾼 뒤에도 물체의 위치와 종류를 제대로 찾는지 확인해야 합니다.

Calibration
대표 입력을 모델에 통과시켜 layer별 activation 범위를 관찰하고 정수 배율의 출발점을 잡는 과정입니다.
Quantization scale
실수값과 정수값 사이의 대응 관계입니다. RTL에서는 multiplier와 shift 조합으로 같은 변환을 수행합니다.
Wide accumulation
INT8 곱을 바로 8-bit로 줄이지 않고 INT32에 더해 중간 합의 overflow와 정보 손실을 줄입니다.
Requantization
누산 결과에 bias와 활성화를 적용한 뒤 multiplier·round offset·shift·clamp를 거쳐 다음 8-bit 범위로 바꾸는 단계입니다.
Detector mAP
중간 tensor 오차가 아니라 최종 bounding box와 class 결과를 기준으로 양자화 품질을 판단한 지표입니다.

FPGA 구현의 출발점이 된 INT8 양자화

YOLOv2의 feature map과 weight는 layer마다 값의 범위가 다릅니다. 이 값을 모두 8-bit 정수로 저장하면 DDR에서 옮겨야 하는 데이터가 줄고, FPGA의 DSP를 정수 곱셈에 활용할 수 있습니다. 하지만 범위를 잘못 정하면 작은 값은 사라지고 큰 값은 8-bit 범위를 넘어가며, 마지막 bounding box와 class score도 달라집니다.

대표 이미지와 detector mAP를 이용한 배율 탐색

calibration은 고정 seed 20260213으로 선택한 32장을 사용했습니다. CAPP_testset_close와 CAPP_testset_long에서 각각 16장씩 뽑아 가까운 물체와 먼 물체가 한쪽에 치우치지 않게 구성했습니다. 각 이미지를 정수 모델에 통과시키며 11개 convolution의 activation과 parameter hex를 저장하고 layer별 min/max·clipping 상태를 집계했습니다.

중간 tensor가 소프트웨어 기준값과 얼마나 비슷한지는 오차가 시작된 지점을 찾는 데 유용합니다. 그러나 최종 기준은 검출 결과였습니다. 두 detection head를 모두 후처리한 뒤 mAP가 유지되는 후보를 선택했습니다. mAP는 여러 물체 종류에서 예측 상자와 정답 상자가 얼마나 잘 맞는지를 종합한 정확도 지표입니다.

INT8 저장·INT32 누산·requantization 데이터 경로

INT8 저장

feature map은 layer 조건에 맞는 8-bit, weight는 signed INT8로 보관해 DDR 전송량과 내부 buffer 사용량을 줄입니다.

INT32 누산

많은 INT8 곱을 더하는 동안 값이 넘치지 않도록 더 넓은 정수에 합을 보관합니다.

Bias와 활성화

누산 결과에 bias를 더하고, 해당 layer의 조건에 따라 ReLU를 적용합니다.

Requantization

multiplier와 round offset을 더한 뒤 shift하고, unsigned 0–255 또는 signed −128–127로 clamp합니다.

fastv2_postproc_requant_pipe.v · 8-bit 범위로 제한하는 부분 
if ((ENABLE_SIGNED != 0) && signed_mode) begin
  if (value > 127)       clamp_byte = 8'h7f;
  else if (value < -128) clamp_byte = 8'h80;
  else                    clamp_byte = value[7:0];
end else begin
  if (value < 0)         clamp_byte = 8'h00;
  else if (value > 255)  clamp_byte = 8'hff;
  else                    clamp_byte = value[7:0];
end

이 단계의 실제 파이프라인은 fastv2_postproc_requant_pipe.v에서 확인할 수 있습니다.

최종 CONV00 계수로 계산한 예

최종 RTL source의 CONV00은 requant_mul=1,006,507, requant_shift=28, requant_round=0을 사용합니다. bias와 ReLU를 적용한 INT32 값이 18,432라면 다음처럼 8-bit 출력 69가 만들어집니다.

product = 18,432 × 1,006,507 = 18,551,937,024
shifted = product >> 28 = 69
clamp_unsigned(69) = 69

이 최종 설정에서는 round offset이 0이므로 양수 값은 right shift에서 잘립니다. signed 출력의 음수는 절댓값을 shift한 뒤 부호를 되돌려 0 방향으로 자르고, 마지막에 −128–127 범위로 제한합니다. 즉 모든 layer에 무조건 round-to-nearest를 적용했다고 표현하지 않습니다.

정확도와 timing을 함께 확인한 이유

정수 모델과 같은 결과를 만드는 계산식이라도 한 클록 안에 긴 곱셈과 덧셈을 모두 지나면 FPGA timing을 맞추기 어렵습니다. requantization 회로에서는 32-bit 계수를 두 부분으로 계산하고, 곱셈과 합산 사이에 레지스터를 두었습니다. 이어지는 반올림, shift와 clamp도 여러 파이프라인 단계로 흘러갑니다.

중요한 점은 파이프라인을 추가한 뒤에도 모델에서 정한 배율, round offset과 clamp 규칙이 그대로 유지돼야 한다는 것입니다. 소프트웨어 양자화와 RTL이 같은 숫자의 의미를 공유해야 최종 detector 결과도 일치합니다.

이 단계에서 한 일

대표 이미지 집합을 구성하고 layer별 배율 후보를 반복 평가하는 흐름을 정리했습니다. 후보마다 정수 추론과 detector mAP를 계산해 결과를 기록했으며, 선택한 multiplier·round offset·shift 규칙이 소프트웨어와 requantization RTL에서 같은 순서로 적용되는지 확인했습니다.
