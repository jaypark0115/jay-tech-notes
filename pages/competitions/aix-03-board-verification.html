3. 한 장의 동작 확인을 229장 평가로 확장하기

한 이미지에서 검출 상자가 보인다는 사실만으로 가속기 전체가 정확하다고 말할 수는 없습니다. 먼저 한 장으로 FPGA program부터 결과 후처리까지 모든 단계를 확인하고, 같은 실행 환경에서 229장을 차례로 처리했습니다. 마지막에는 처리 속도뿐 아니라 두 detection head의 mAP와 하드웨어 timing 보고서도 함께 확인했습니다.

Smoke test
한 장으로 program, preload, compute, readback과 후처리 경로가 끊기지 않는지 빠르게 확인하는 테스트입니다.
Layer mismatch
소프트웨어와 FPGA tensor가 처음 달라지는 layer를 찾아 주소, signed 처리와 양자화 도메인 문제를 좁히는 방법입니다.
Compute-only FPS
FPGA cycle counter가 잰 순수 연산 속도로, JTAG 전송과 Python 후처리 시간을 포함하지 않습니다.
Detector-level mAP
두 head의 출력을 실제 box와 class로 해석해 229장 전체에서 검출 정확도를 평가합니다.
Timing closure
모든 데이터 경로가 목표 100MHz의 setup·hold 시간을 만족해 실제 bitstream을 만들 수 있는 상태입니다.

229장 test set과 detector 평가 조건

최종 평가는 로컬 target list에 기록된 CAPP_testset_close와 CAPP_testset_long 이미지 229장을 사용했습니다. 가까운 구도와 먼 구도를 모두 포함한 test set이며, 원본 1920×1080 이미지를 FPGA 입력용 256×256×3으로 준비했습니다. 정답은 class와 정규화된 중심 좌표·폭·높이를 적는 YOLO text annotation이고, 모델은 60개 class를 출력합니다.

test_one: program부터 detector 후처리까지 점검

test_one은 단순한 데모 스크립트가 아니라 실행 경로의 각 단계를 확인하기 위한 테스트입니다. 문제가 생기면 어느 단계부터 값이 달라졌는지 좁힐 수 있도록 아래 순서로 진행됩니다.

  1. Program: 최종 bitstream을 FPGA에 올립니다.
  2. Preload: 정수 weights와 입력 tensor를 DDR에 기록합니다.
  3. Compute: 제어 레지스터로 실행을 시작하고 done 신호와 cycle 수를 읽습니다.
  4. Readback: 8×8 CONV14와 16×16 CONV20 결과를 모두 가져옵니다.
  5. Postprocess: 두 head를 해석하고 NMS를 적용해 bounding box를 만듭니다.

test_all: 한 번의 program·weight preload로 229장 연속 실행

이미지마다 bitstream과 weights를 다시 올리면 FPGA 계산 시간과 준비 시간이 섞입니다. test_all에서는 bitstream program과 weight preload를 한 번 수행한 뒤 입력 이미지만 바꾸며 229장을 처리했습니다. 각 이미지의 cycle 수와 두 head 출력을 저장한 다음, 모두 끝난 뒤 같은 detector evaluator로 mAP를 계산했습니다.

두 detection head를 함께 평가한 78.60% detector mAP

mAP는 각 이미지에서 물체를 하나 찾았는지만 세는 값이 아닙니다. 예측한 상자와 정답 상자의 겹침, 물체 종류와 confidence를 함께 반영해 전체 데이터에서 검출 품질을 평가합니다. 여기서는 8×8 CONV14와 16×16 CONV20을 모두 사용한 FPGA 출력에 같은 detector 후처리를 적용해 78.60%를 확인했습니다.

개발 중 얻은 일부 속도 수치는 한쪽 head만 계산하거나 진단용 조건에서 측정한 값이므로 최종 결과에 사용하지 않았습니다. 229장 처리 완료, 두 head의 mAP와 timing 조건이 모두 확인된 build의 수치만 위에 적었습니다.

추가 5%p 차이는 단일 원인으로 확정하지 않았습니다

저장된 layer readback과 최종 CSV에는 software reference와 FPGA detection head 사이의 byte mismatch가 남아 있습니다. 이 차이가 detector mAP 감소와 함께 관찰됐지만, 한 요인만 분리한 ablation 결과는 없습니다. 따라서 원인을 확정형으로 쓰지 않고 아래 항목을 재검증 우선순위로 남겼습니다.

  • requantization의 signed/unsigned 모드, right-shift와 clamp 경계
  • Route·Upsample 뒤 HWC packing과 DDR offset
  • CONV14·CONV20 head별 scale 및 readback 변환
  • software와 FPGA 후처리의 score 해석과 class-wise NMS 입력
이미지 증빙의 범위 보관된 최종 패키지에는 한 사례의 software–FPGA two-head 비교 이미지가 남아 있습니다. 229장 전체의 성공·약화·실패 사례를 같은 형식으로 export한 묶음은 확인되지 않아, 대표 실패 이미지를 임의로 분류하거나 새 결과처럼 제시하지 않았습니다. 최종 품질은 개별 화면 대신 전체 mAP와 TP/FP/FN으로 판단했습니다.

최초 mismatch layer를 기준으로 한 오류 추적

  • 소프트웨어와 FPGA tensor가 처음 달라지는 layer를 찾아 주소와 정수 도메인을 확인했습니다.
  • Route와 Upsample은 feature map 배치와 DDR offset을 descriptor와 readback 결과로 비교했습니다.
  • MAC 병렬도를 바꾼 뒤에는 DSP 수뿐 아니라 routing과 requantization timing을 다시 확인했습니다.
  • CONV20만 실행하는 빠른 진단용 build와 두 head를 모두 계산하는 최종 build를 구분했습니다.

프로젝트에서 맡은 일

대표 이미지와 detector mAP를 이용한 양자화 조건 탐색, 정수 모델과 RTL 데이터 형식의 연결, full-graph 가속기 통합과 병목 개선, FPGA 보드 검증과 실행 자료 정리를 맡았습니다. 팀 프로젝트이므로 특정 RTL 모듈 전체를 개인이 단독으로 작성했다는 의미는 아닙니다.

한 장 테스트와 229장 테스트가 같은 bitstream, weights와 후처리 규칙을 사용하도록 실행 경로를 정리했습니다. 덕분에 화면에 보이는 검출 결과, cycle 기반 속도, detector mAP와 Vivado 보고서를 같은 구현 기준으로 비교할 수 있었습니다.
