YOLOv2의 두 검출 경로를 한 번의 FPGA 실행으로 연결하기

이 프로젝트는 convolution 한 층만 빠르게 만드는 데서 끝나지 않았습니다. 256×256 RGB 입력에서 60개 클래스를 검출하는 YOLOv2를 정수화하고, Conv·Pool·Route·Upsample과 8×8·16×16 두 detection head가 이어지는 전체 그래프를 Nexys 4 DDR에서 실행했습니다. 정확도, 처리 속도, timing과 자원을 같은 최종 bitstream 기준으로 확인했습니다.

무엇을 만든 프로젝트인가

Python host가 입력과 weight를 DDR에 적재하고, FPGA의 descriptor scheduler가 22개 처리 단계를 순서대로 실행합니다. 144개 packed MAC lane이 convolution을 담당하며 Pool, Route, Upsample을 거쳐 두 detection head를 DDR에 저장합니다. host는 결과를 읽어 같은 detector 후처리와 mAP 평가에 연결합니다.

정확한 정수 모델과 끝까지 실행되는 데이터 경로가 모두 필요했습니다

YOLOv2는 convolution만 반복하지 않습니다. 서로 다른 해상도의 feature map을 저장하고 다시 불러오는 Route, 2배 해상도를 만드는 Upsample, 두 크기의 detection head가 함께 동작합니다. 한 연산기의 peak 처리량이 높아도 DDR 주소, layer별 scale과 head readback이 어긋나면 최종 검출 결과는 나오지 않습니다.

Host와 FPGA의 역할을 나누고 DDR에서 연결했습니다

01 · Host 입력·weight 준비 전처리와 DDR preload
02 · JTAG-to-AXI DDR workspace 32-bit HWC packing
03 · FPGA 22 descriptor 실행 Conv · Pool · Route · Upsample
04 · Two heads CONV14 · CONV20 8×8과 16×16 출력 저장
05 · Host Decode · NMS · mAP 동일한 detector 평가 경로

최종 구조는 발표 후반의 sign-off 자료와 실제 RTL을 기준으로 정리했습니다

최종 발표 앞부분에는 개발 중간 구조인 19개 연산 단계와 192 MAC/cycle이 남아 있습니다. 후반의 최종 구현 섹션, 보관된 XPR과 RTL에서는 22개 descriptor와 144개 packed lane이 확인됩니다. 이 페이지는 두 버전을 섞지 않고 최종 구현 값을 사용합니다.

항목중간 설계 설명이 페이지의 최종 기준
그래프 단계19개 연산 단계RTL descriptor 22개
MAC 병렬도16-lane × 12 group = 192144 packed MAC lane
성능 판단중간 FPS 실험229장 최종 cycle counter
정확도 판단layer mismatch 중심두 head detector mAP 78.60%

144개 lane은 한 weight와 두 activation을 packed 방식으로 처리합니다. 구조적으로 한 accepted cycle에 288개의 scalar product가 가능하지만, 이를 전체 그래프의 지속 처리량과 같은 값으로 표현하지 않습니다.

제가 맡은 일은 정수 모델과 최종 보드 결과 사이를 잇는 작업이었습니다

229장 모두에서 FPGA 실행과 두 head readback이 완료됐습니다. 평균 8,756,040 cycles, 87.560404ms로 계산한 11.420687 FPS는 FPGA cycle counter 기준이며 JTAG 전송, Python 전처리와 후처리는 포함하지 않습니다. INT8 software reference는 83.60% mAP, FPGA detector는 78.60% mAP였습니다.

전력 1.842W는 Vivado routed design 추정값이며 confidence는 Low입니다. 보드 전력 실측이나 확정적인 에너지 효율 수치로 사용하지 않습니다.
