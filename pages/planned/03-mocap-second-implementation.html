4카메라 모션캡처 시스템 2차 구현

1차 구현에서는 Jetson과 동기화 카메라 4대를 연결하고 체커보드의 3차원 이동을 추적했습니다. 이번에는 직접 선정·조립한 Crazyflie에 IR Active Marker를 장착하고, 네 카메라가 계산한 위치를 BLE로 다시 기체에 전달해 상승·중심 유지·착륙까지 하나의 폐루프로 연결했습니다. 화면에서 점을 찾는 단계가 실제 드론을 제어하는 시스템으로 확장된 과정입니다.

1차 구현에서 2차 구현으로

체커보드 추적 → 실제 드론 조립 → IR LED 추적 → 3차원 위치 계산 → BLE 외부 위치 전달 → 폐루프 호버·착륙

1. 체커보드 추적을 실제 드론 제어로 확장

1차 구현의 목표는 카메라 보정, 월드 원점 설정과 체커보드 궤적 표시였습니다. 그 기반을 유지하면서 표적만 드론으로 바꾼 것이 아니라, 위치 결과를 다시 기체의 상태 추정과 비행 제어에 넣는 왕복 경로를 추가했습니다. 카메라가 관측한 드론 위치가 Jetson에서 계산되고, 계산된 위치가 무선으로 기체에 전달되며, Crazyflie 내부 위치 제어기가 목표점과 현재 위치의 차이를 줄이도록 자세와 모터 출력을 조절합니다.

  1. 관측4대의 OV9281 카메라가 드론의 IR LED 마커를 같은 촬영 주기로 관측합니다.
  2. 측위Jetson이 카메라별 LED 점을 검출하고 보정값을 이용해 드론의 3차원 위치·방향을 계산합니다.
  3. 전달계산한 외부 위치를 BLE 통신으로 Crazyflie 상태 추정기에 보냅니다.
  4. 제어기체 내부 위치 제어기가 목표 위치를 유지하도록 보정하며, Jetson은 명령·상태·궤적을 기록합니다.

2. 드론을 직접 선정하고 IR 마커 기체로 조립

외부 위치를 받아 내부 위치 제어에 사용할 수 있고, 소형 실내 실험에 적합한 Crazyflie 2.1+와 Active Marker Deck을 선정했습니다. 카메라·Jetson 프로그램과의 연결 가능성, BLE 통신, 기체의 기존 상태 추정·위치 제어 기능을 함께 검토한 뒤 과제 장비로 확보했습니다. 수령한 기체는 모터·프로펠러·배터리와 마커 데크를 직접 조립하고, LED 방향과 기체 전방축을 확인해 기존 모션캡처 시스템에 연결했습니다.

3. 카메라–Jetson–드론을 잇는 전체 시스템

하드웨어는 카메라 어레이, Jetson 연산부, Crazyflie와 모니터링 PC의 네 블록으로 나뉩니다. OV9281 카메라 4대의 영상은 CamArray HAT를 거쳐 MIPI CSI-2로 Jetson에 들어옵니다. Jetson은 영상 처리와 3차원 위치 계산, 실험 기록과 비행 명령을 담당하고, 드론과는 BLE로 위치·명령과 상태·응답을 주고받습니다. 브라우저 화면은 같은 네트워크로 Jetson의 영상, 계산 위치, 목표 경로와 기체 상태를 표시합니다.

4. 동기화된 네 영상에서 드론 위치를 계산하는 방법

현재 Jetson 배포 프로그램은 B0267이 보내는 5120×800 한 장의 합성 프레임을 입력으로 받습니다. 이 프레임 안에는 1280×800 영상 네 장이 가로로 이어져 있습니다. 프로그램은 한 합성 프레임을 네 구간으로 나누고, 네 결과에 같은 capture_cycle_id와 촬영 시각을 붙입니다. 따라서 서로 다른 시각의 화면을 임의로 모으는 대신, 같은 캡처 주기의 네 시점을 한 세트로 위치 계산에 사용합니다.

01한 번에 촬영

CamArray가 동기화한 네 흑백 영상을 하나의 합성 프레임으로 전달합니다.

024채널 분리

Jetson이 5120×800 영상을 1280×800 카메라 영상 네 장으로 분리합니다.

03IR LED 검출

카메라별 밝은 점을 찾고 Active Marker의 LED 배치와 대응시킵니다.

04다중 시점 결합

카메라 보정값과 여러 관측을 이용해 드론의 3차원 위치·방향을 계산합니다.

05좌표 변환·전달

월드 좌표를 실험 시작점 기준 비행 좌표로 바꿔 기록·화면·BLE 전송에 사용합니다.

IR LED는 주변 조명과 반사점에 영향을 받기 때문에 자동 밝기만 사용하지 않았습니다. 실제 촬영 화면을 보며 네 카메라의 노출값과 아날로그 게인을 직접 조절해 마커는 분명하게 남고 배경은 어둡게 보이도록 맞췄습니다. 이 설정과 캡처 주기, 검출 결과와 유효 카메라 수를 함께 기록해 영상과 위치 데이터를 다시 대조할 수 있게 했습니다.

5. 카메라·추적·비행을 한 화면에서 확인

1차 구현의 Viewer·Calibration·World Origin·Tracking 흐름을 유지하면서 Drone, Open-Loop Flight, Closed-Loop Flight와 실험 화면을 뒤에 연결했습니다. 카메라 영상, 현재 3차원 위치, 목표 경로, 실제 MoCap 궤적, BLE 상태와 실험 진행 단계를 한 화면에서 확인할 수 있습니다. 실험 화면에서는 목표 경로를 옅게, 실제 측정 경로를 진하게 표시해 드론이 명령을 얼마나 따라갔는지 바로 비교하도록 구성했습니다.

6. 모션캡처 위치를 이용한 호버와 착륙

비행에서는 이륙 직전의 위치를 목표 중심으로 고정합니다. 드론이 옆으로 움직이면 네 카메라가 그 변화를 관측하고 Jetson이 계산한 위치를 Crazyflie에 전달합니다. 기체 내부 위치 제어기는 추정 위치와 목표의 차이를 줄이는 방향으로 자세를 조정합니다. 상승·중심 유지·하강·착륙을 각각 기록하고, 목표와 실제 MoCap 궤적을 함께 남겨 단순히 모터가 도는 것이 아니라 위치 피드백이 연결됐는지 확인했습니다.

다음 비행 기능은 한 점 호버에서 끝내지 않고, 직선·왕복·원과 같은 기준 경로를 거쳐 특정 모양을 그리며 비행하는 궤적 추종으로 확장할 예정입니다. 목표 경로와 실제 경로를 같은 좌표계에 기록해 형상 오차와 반복성을 비교하는 것이 다음 단계입니다.

7. GitHub PR을 이용한 팀 협업

장비 선정, Jetson·카메라·드론 프로그램 연동과 통합 시험은 제가 중심이 되어 진행했고, 팀원들은 케이지 구조물과 카메라 장착부 제작을 맡았습니다. 변경 사항은 GitHub에서 브랜치와 PR 단위로 나누어 공유하고, 실제 장비에 합치기 전에 수정 범위와 인터페이스를 함께 확인했습니다. 하드웨어 제작과 소프트웨어 통합이 따로 진행되지 않도록 케이지 크기, 카메라 방향, 케이블 통과 위치와 장착 방식을 계속 맞췄습니다.

8. 케이지와 1:1 카메라 케이스 제작

반복 비행과 정량 측정을 위해 팀원들과 보호 케이지를 제작하고 있습니다. 파이프 구조를 조립하고 카메라가 들어갈 위치를 확인하면서, 케이지가 완성된 뒤에도 네 카메라의 상대 위치와 방향이 쉽게 변하지 않도록 장착 방식을 함께 검토했습니다.

실제 PCB 크기에서 시작한 카메라 장착 설계

카메라 모듈을 케이지에 정확히 고정하려면 PCB와 렌즈, 리본 케이블의 크기를 먼저 맞춰야 했습니다. 보유한 OV9281 카메라 PCB를 기준으로 CAD에서 1:1 비율의 모델을 만들고, 앞·뒤면 부품과 렌즈 돌출 높이까지 표현해 케이지 제작팀에 전달했습니다. 이 모델을 기준으로 케이스와 덮개, 파이프 체결부를 출력하고 실제 PCB와 대조하면서 홀 위치와 케이블 여유를 조정했습니다.

9. 케이지 완성 후 정확도 측정과 논문 정리

현재까지 카메라 입력, 보정·원점, Active Marker 위치 추정, BLE 외부 위치 전달과 실제 호버·착륙을 하나의 시스템으로 연결했습니다. 케이지와 카메라 고정 구조가 완성되면 네 카메라를 고정한 상태에서 다시 보정하고, 기준 위치와 반복 경로를 이용해 위치 오차와 재현성을 측정할 예정입니다. 이후 직선·원·지정 모양 궤적의 목표값과 실제 비행 경로를 비교해 결과를 정리하고, 정확도 측정과 논문 작성까지 마무리할 계획입니다.
