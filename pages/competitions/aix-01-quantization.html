1. 양자화 숫자를 고르는 일이 아니라 좌표계를 맞추는 일

YOLOv2를 FPGA로 옮길 때 첫 문제는 MAC을 만드는 것이 아니었다. 각 layer의 activation과 weight가 서로 다른 범위를 가지는데, 이를 INT8로 저장하면서도 마지막 bounding box 결과를 유지해야 했다. 그래서 대표 이미지로 범위를 관찰하고, 후보 정수 배율을 적용한 뒤 detector mAP가 개선되는 조합만 남기는 방식으로 양자화 조건을 잡았다.

핵심 기준 중간 tensor의 byte 일치율은 디버깅 신호로 사용하고, 최종 선택은 CONV14와 CONV20 두 detection head를 함께 후처리한 detector mAP로 했다. 특정 multiplier 숫자 목록보다 이 선택 과정과 데이터 도메인의 일관성을 중심으로 설명한다.

1.1 float graph를 그대로 줄이면 layer 사이의 의미가 어긋난다

floating-point 모델에서는 작은 소수와 큰 누산값이 같은 자료형 안에서 자연스럽게 표현된다. INT8 datapath에서는 feature map을 저장하는 범위, weight 범위, bias가 더해지는 누산 범위와 다음 layer가 기대하는 입력 범위를 명시해야 한다. 한 layer의 출력이 8-bit 안에 들어온다는 사실만으로 다음 layer와 같은 수치 도메인이라는 보장은 없다.

representative images → candidate scales → detector mAP → fixed-point RTL

1.2 후보를 만들고, 실제 검출 결과가 좋아질 때만 채택했다

  1. 대표 입력 선택: 가까운 물체와 먼 물체가 함께 포함되도록 이미지를 구성해 layer별 activation 범위를 관찰했다.
  2. 후보 생성: 한 번에 전체 값을 크게 바꾸지 않고 layer별 배율 주변의 후보를 만들었다.
  3. 정수 추론: 후보 조합으로 quantized inference와 detector 후처리를 실행했다.
  4. mAP 평가: tensor 오차가 작아도 검출 결과가 나빠지면 채택하지 않고, mAP가 좋아지는 후보만 유지했다.
  5. 반복 방지: 이미 시도한 조합과 계속 악화되는 방향을 기록해 같은 실험을 반복하지 않도록 했다.

이 흐름은 “가장 큰 값을 127에 맞춘다”는 한 번의 계산이 아니라, quantization error가 YOLO 후처리를 지나 실제 box와 class score에 어떤 영향을 주는지 확인하는 feedback loop다.

1.3 하드웨어에서는 저장 폭과 누산 폭을 분리했다

INT8 feature / weight

DDR과 내부 buffer에서 이동하는 데이터 양을 줄이고 DSP 입력 폭에 맞춘다.

INT32 accumulation

여러 INT8 곱의 합을 8-bit에 바로 넣지 않고 더 넓은 누산 범위에 보존한다.

Bias + activation

누산 결과에 bias를 더하고 layer 조건에 따라 ReLU를 적용한다.

Requantization

곱셈, rounding, shift와 clamp로 다음 layer의 8-bit 도메인에 맞춘다.

fastv2_postproc_requant_pipe.v - bias, ReLU, multiplier 전달 
wire signed [SRC_W-1:0] sum_bias_w =
    $signed({{(SRC_W-ACC_W){i_sum[ACC_W-1]}}, i_sum}) +
    $signed({{(SRC_W-ACC_W){i_bias[ACC_W-1]}}, i_bias});

src0   <= (i_relu_en && (sum_bias_w < 0))
        ? {SRC_W{1'b0}} : sum_bias_w;
mul0   <= i_requant_mul;
round0 <= i_requant_round;
shift0 <= i_requant_shift;
fastv2_postproc_requant_pipe.v - signed/unsigned 8-bit clamp 
if ((ENABLE_SIGNED != 0) && signed_mode) begin
  if (value > 127)       clamp_byte = 8'h7f;
  else if (value < -128) clamp_byte = 8'h80;
  else                    clamp_byte = value[7:0];
end else begin
  if (value < 0)         clamp_byte = 8'h00;
  else if (value > 255)  clamp_byte = 8'hff;
  else                    clamp_byte = value[7:0];
end

1.4 정확도 규칙을 유지하면서 timing도 닫아야 했다

최종 requantizer는 32-bit coefficient를 두 16-bit partial product로 나누고, 곱셈과 합산 사이에 register를 둔다. 한 cycle에 긴 DSP-to-DSP 경로를 만들지 않으면서도 동일한 fixed-point multiplier 규칙을 유지하기 위한 구조다. 이후 rounding, shift, clamp를 단계별로 pipeline해 throughput 1의 post-processing 경로로 연결했다.

fastv2_postproc_requant_pipe.v - coefficient 분할과 pipeline 
prod_lo1 <= $signed(src0)
          * $signed({1'b0, mul0[15:0]});
prod_hi1 <= $signed(src0)
          * $signed({1'b0, mul0[31:16]});

prod2 <= sign_extend(prod_lo1)
       + (sign_extend(prod_hi1) <<< 16);

공개한 실제 RTL 스냅샷은 fastv2_postproc_requant_pipe.v에서 확인할 수 있다.

1.5 양자화에서 얻은 결론

모델 정확도와 하드웨어 데이터 경로는 별개 단계가 아니었다. mAP로 선택한 layer별 수치 규칙이 RTL의 INT8 입력, INT32 누산, rounding과 clamp에 같은 의미로 고정되어야 했다. 이 연결이 어긋나면 각 모듈이 정상 동작해도 최종 detector는 다른 좌표계를 해석하게 된다.
