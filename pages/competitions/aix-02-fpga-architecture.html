2. MAC 모듈이 아니라 YOLO graph 전체를 실행하는 구조

YOLOv2는 convolution만 반복하는 직선형 네트워크가 아니다. Pooling, route, upsample과 두 detection head가 서로 다른 feature map을 참조한다. 최종 구조는 host가 layer마다 명령하는 대신, FPGA 내부 descriptor와 dispatcher가 22개 stage의 shape, operation, DDR offset을 읽고 다음 layer를 실행하도록 구성했다.

시스템 경계 Host는 bitstream program, weights/input preload, 시작·완료 제어, result readback과 detector 후처리를 담당한다. FPGA는 DDR의 정수 tensor를 읽어 CONV14와 CONV20 두 detection head까지 graph를 계산한다.

2.1 Host에서 검출 결과까지

Python host → JTAG-to-AXI → DDR workspace → RTL scheduler → two heads → mAP

UART 대신 JTAG-to-AXI를 사용한 이유는 tensor와 weight 전송량 때문이다. FPGA compute-only 시간은 약 0.08756초인데 UART 115200bps에서는 입력과 출력 전송만 이미지당 수십 초가 필요하다. JTAG-to-AXI를 통해 DDR와 control register에 직접 접근해 계산 자체와 통신 병목을 구분했다.

2.2 layer shape와 DDR 주소를 descriptor로 고정했다

fastv2_network_desc_rom.v에는 각 stage의 operation type, 입력·출력 크기, kernel/stride/pad와 IFM/OFM/weight/bias/scale offset이 들어 있다. scheduler는 layer index를 증가시키며 descriptor를 읽고, op dispatcher가 Conv, Pool, Route, Upsample 또는 Detection 경로를 선택한다.

fastv2_network_desc_rom.v - graph descriptor 예시 
8'd14: begin
  o_layer_type=1;             // CONV14
  o_in_w=8;  o_in_h=8;  o_in_c=512;
  o_out_w=8; o_out_h=8; o_out_c=195;
  o_kernel=1; o_stride=1; o_pad=0;
end

8'd18: begin
  o_layer_type=4;             // upsample x2
  o_in_w=8;   o_in_h=8;   o_in_c=128;
  o_out_w=16; o_out_h=16; o_out_c=128;
end

8'd19: begin
  o_layer_type=3;             // route / concat
  o_in_c=128; o_out_c=384;
  o_ifm2_word_ofs=614400;
end

실제 descriptor 전체는 fastv2_network_desc_rom.v에서 확인할 수 있다. 이 표가 있어 host는 각 layer의 DDR 주소를 매번 계산해 명령하지 않아도 된다.

2.3 144개 INT8 lane을 연산 형태에 맞게 재사용했다

3×3 convolution에서는 144개 signed INT8 lane이 같은 weight를 공유하며 두 spatial dot product를 계산한다. 1×1에서는 같은 DSP array를 네 output channel과 2×2 spatial tile에 맞게 다시 그룹화한다. MAC 수를 추가하지 않고 layer 형태에 따라 lane의 의미를 바꾼 것이다.

fastv2_mac_array_packed_pair.v - packed-pair 입력 구성 
parameter integer NUM_MACS = 144,
parameter integer DATA_W   = 8,
parameter integer ACC_W    = 32;

assign pack_a[gi] =
    {1'b0, ifm1_byte[gi][7:0], 16'd0}
  | {17'd0, ifm0_u[gi]};
assign pack_b[gi] =
    {{10{wgt_byte[gi][7]}}, wgt_byte[gi]};
assign product_w[gi] = pack_a[gi] * pack_b[gi];

144개 INT8 곱의 local reduction은 signed 23-bit 안에 들어가도록 분석하고, layer 간 누산과 post-processing은 32-bit로 유지했다. 실제 구현은 fastv2_mac_array_packed_pair.v에 공개했다.

2.5 빠른 smoke build와 유효한 detector를 구분했다

개발 중에는 16×16 CONV20 경로만 남겨 속도를 확인한 smoke build도 있었다. 그러나 YOLO 후처리는 8×8 CONV14와 16×16 CONV20 두 head가 모두 있어야 한다. 최종 RTL에서는 CONV14를 건너뛰는 경로를 비활성화하고, 두 결과를 DDR에 보존해 host가 함께 읽도록 했다.

yolo_engine.v - full detector에서 두 head 보존 
// CONV20-only smoke builds skipped layers 13/14 after layer12,
// but detector postprocess needs both CONV14 and CONV20.
wire fastv2_skip_l13_l14_head_active = 1'b0;

이 수정은 “더 높은 FPS”보다 “정확도 평가가 가능한 전체 모델”을 최종 기준으로 삼았다는 의미다. 최종 성능 수치는 두 head를 모두 계산한 bitstream에서만 보고한다.
