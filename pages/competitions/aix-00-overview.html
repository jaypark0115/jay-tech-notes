YOLOv2 Full-Graph FPGA 가속기

AIX 2026의 과제는 학습된 딥러닝 모델을 실제 FPGA 가속기로 구현하는 것이었다. 프로젝트에서는 256×256 RGB 이미지에서 60개 상품 클래스를 검출하는 YOLOv2를 대상으로 삼았다. Convolution 하나의 데모를 만드는 데서 멈추지 않고, Pool·Route·Upsample과 8×8·16×16 두 detection head까지 이어지는 전체 추론 그래프를 Nexys 4 DDR에서 실행했다. Software에서 정한 INT8 양자화 조건, DDR 주소와 packing, descriptor 기반 scheduler, packed MAC, 두 head readback과 detector 후처리가 하나의 실행 경로로 연결된다. 아래 수치와 결과 이미지는 모두 같은 최종 bitstream과 229장 평가 세트를 기준으로 한다.

프로젝트 개요

Python host가 입력 이미지와 양자화 weight를 DDR에 적재하고 시작 레지스터를 설정하면, FPGA의 descriptor scheduler가 22개 처리 단계를 순서대로 실행한다. 144개 packed MAC lane이 convolution을 계산하고, 전용 경로가 Pool·Route·Upsample을 처리한다. 마지막 CONV14와 CONV20 detection head는 DDR의 서로 다른 주소에 보존된다. Host는 두 tensor를 읽어 같은 decode와 NMS를 적용하고 detector mAP를 계산한다. 중간 feature와 weight는 8-bit로 저장하고, 곱셈의 합은 32-bit로 누적한 뒤 layer별 requantization을 거쳐 다시 8-bit로 저장한다.

경진대회 과제와 구현 범위

객체 검출은 입력 이미지를 읽어 최종 상자를 그리는 하나의 함수처럼 보이지만, 하드웨어에서는 여러 시스템으로 나뉜다. 학습된 모델을 정수로 바꾸는 software reference, 대용량 tensor를 저장하는 DDR, layer를 순서대로 실행하는 RTL, 보드에 데이터를 넣고 결과를 회수하는 host, raw detection tensor를 실제 상자로 바꾸는 후처리가 모두 맞아야 한다. 이 프로젝트의 FPGA 구현 범위는 입력 이후부터 CONV14·CONV20 두 head를 만드는 신경망 연산 그래프까지이다. 이미지 전처리, bitstream program, DDR preload·readback, decode·NMS·mAP 평가는 host가 담당한다.

Model YOLOv2 60-class 256×256 입력 · two-head detector
Quantization INT8 · INT32 · requant 11개 convolution scale
Dataflow DDR workspace HWC 4-byte packing · global reuse
RTL 22 descriptors · 144 lanes Conv · Pool · Route · Upsample
Validation 229-image detector mAP 같은 bitstream으로 보드 반복 실행

“Full graph”라는 표현도 이 경계를 따른다. 학습이나 NMS까지 FPGA에 포함했다는 뜻이 아니라, YOLOv2가 두 detection head를 만들기까지 필요한 Conv·Pool·Route·Upsample 연산을 FPGA 내부 scheduler가 실행한다는 뜻이다. 정확도는 FPGA가 계산한 두 head를 host의 동일한 후처리에 넣어 평가했다.

객체 검출과 FPGA 가속

객체 검출 모델은 이미지에 어떤 물체가 있는지만 분류하지 않는다. 물체의 위치를 나타내는 경계 상자와 클래스 확률을 동시에 계산해야 한다. YOLOv2는 입력 이미지에서 단계적으로 특징을 추출하고, 서로 다른 크기의 feature map을 결합한 뒤, 두 detection head에서 작은 물체와 큰 물체에 대응하는 후보를 만든다. 마지막 decode와 NMS는 겹치는 후보를 정리해 최종 검출 상자를 남긴다.

FPGA에서는 많은 곱셈을 병렬화할 수 있지만, 연산기 수만 늘린다고 전체 모델이 자동으로 빨라지지는 않는다. 매 layer의 입력과 weight를 DDR에서 읽고, 중간 feature map을 정해진 주소에 저장하며, Route가 과거 결과를 다시 읽도록 관리해야 한다. 정수 scale이나 주소가 한 layer에서만 어긋나도 뒤의 모든 출력이 달라진다. 이 때문에 이 프로젝트는 MAC 배열뿐 아니라 메모리 배치, layer 제어, 정수 후처리, 보드 readback을 하나의 시스템으로 다룬다.

용어이 프로젝트에서의 의미
Feature map각 convolution이 만든 중간 특징값 배열이며 DDR과 내부 buffer에 저장된다.
Weight학습으로 얻은 convolution 계수이며 INT8 형식으로 FPGA에 공급된다.
Descriptor연산 종류, tensor 크기, DDR 주소, scale을 한 단계씩 지정하는 제어 정보이다.
Detection head경계 상자, 물체 존재 확률, 클래스 점수를 담는 최종 tensor를 만든다.
mAP여러 클래스의 검출 정확도를 한 값으로 요약한 지표이며 단순 tensor 일치율과 다르다.

설계 대상

YOLOv2는 convolution뿐 아니라 서로 다른 해상도의 feature map을 다시 읽는 Route, 2배 해상도를 만드는 Upsample, 두 크기의 detection head를 포함한다. DDR 주소, layer별 scale, head readback은 detector 결과와 직접 연결되는 데이터 경로 요소이다. 최종 그래프에는 22개의 descriptor가 있으며, 초반 backbone이 시각 특징을 만들고 후반의 분기와 결합이 두 해상도의 검출 출력을 만든다.

Host–FPGA 데이터 경로

시스템은 준비와 평가를 담당하는 host, 대용량 tensor를 보관하는 DDR, 정수 네트워크를 실행하는 FPGA로 나뉜다. host는 원본 이미지를 256×256 RGB로 변환하고 입력과 weight를 JTAG-to-AXI 경로로 DDR에 적재한다. FPGA가 시작 신호를 받으면 scheduler는 descriptor ROM을 0번부터 21번까지 읽으며 연산 종류와 주소를 설정한다. 마지막 두 head가 저장되면 done 신호가 발생하고, host가 tensor를 읽어 decode, NMS, mAP 계산을 수행한다.

01 · Host 입력·weight 준비 전처리와 DDR preload
02 · JTAG-to-AXI DDR workspace 32-bit HWC packing
03 · FPGA 22 descriptor 실행 Conv · Pool · Route · Upsample
04 · Two heads CONV14 · CONV20 8×8과 16×16 출력 저장
05 · Host Decode · NMS · mAP 동일한 detector 평가 경로

32-bit DDR word에는 HWC 순서의 INT8 channel 네 개가 들어간다. 이 packing은 버스 폭을 활용하는 동시에 소프트웨어와 RTL이 byte 순서와 signedness를 정확히 공유해야 한다는 제약을 만든다. 입력은 unsigned RGB이지만 detection head의 logit에는 음수가 필요하므로, backbone의 ReLU 출력과 head 출력을 같은 부호 규칙으로 처리할 수 없다. 이러한 차이는 descriptor와 requantization 설정에 명시된다.

최종 구현 기준

개발 과정에는 병렬도와 그래프 범위가 서로 다른 여러 구현본이 남아 있다. 이 글에서는 최종 제출 패키지의 RTL, 보드 실행 결과, Vivado report가 서로 일치하는 값만 대표 사양으로 사용한다. 네트워크 제어는 descriptor ROM의 22개 항목, MAC 병렬도는 공개 RTL의 NUM_MACS=144, 정확도와 속도는 FINAL_RESULT.txt의 229장 결과가 기준이다.

144개 lane은 한 weight와 두 activation을 packed 방식으로 처리한다. 구조적으로 한 accepted cycle에 288개의 scalar product가 가능하지만, 이를 전체 그래프의 지속 처리량과 같은 값으로 표현하지 않는다.

packed MAC의 288 scalar product는 계산 배열이 입력을 받아들인 한 cycle의 구조적 연산량이다. 네트워크 전체에는 DDR 대기, descriptor 전환, Pool·Route·Upsample, 결과 저장 시간이 함께 존재하므로 288에 100MHz를 곱한 값을 곧바로 실제 처리량으로 사용할 수 없다. 대표 속도는 최종 bitstream에서 측정한 평균 cycle 수로 계산한다.

단일 연산 검증에서 detector 검증까지

개발 초반에는 보드에 명령을 보내고 DDR의 정해진 주소를 읽고 쓰는 bring-up이 선행된다. 그다음 convolution 경로와 layer scheduler를 연결하고, Pool·Route·Upsample을 추가해 full graph로 확장했다. 그래프가 끝까지 실행된 뒤에는 HWC/CHW 배열 순서, 4-byte packing, detection head stride와 signed scale을 맞추는 작업이 이어졌다. 마지막 단계에서는 중간 속도 실험에서 제외됐던 CONV14 branch를 복구하고 CONV14·CONV20을 모두 후처리에 사용하는 최종 검증 경로를 고정했다.

이 과정에서 단일 convolution의 최고 속도와 최종 detector의 완성도는 같은 목표가 아니었다. 두 head를 모두 보존하면 branch 계산과 DDR 저장, readback 비용이 늘지만 실제 detector mAP를 평가할 수 있다. 대표 결과는 중간 속도 상한이 아니라 두 head, timing closure, 229장 평가가 모두 같은 bitstream에서 완료된 최종 구현점으로 통일했다.

담당 범위

확인 가능한 프로젝트 기여는 calibration과 scale 탐색을 포함한 양자화, 정수 데이터 형식과 RTL 전체 경로의 통합·최적화, Nexys 4 DDR 보드에서의 반복 검증, 최종 실행 패키지 정리이다. 팀 프로젝트이므로 공개된 개별 RTL 파일을 특정 개인이 단독 작성했다고 표현하지 않으며, 동작하는 full graph를 만들기 위해 연결하고 검증한 범위를 중심으로 기술한다.

최종 결과

229장 모두에서 FPGA 실행과 두 head readback이 완료된다. 평균 8,756,040 cycles, 87.560404ms로 계산한 11.420687 FPS는 FPGA cycle counter 기준이며 JTAG 전송, Python 전처리와 후처리는 포함하지 않는다. INT8 software reference는 83.60% mAP, FPGA detector는 78.60% mAP이다.

전력 1.842W는 Vivado routed design 추정값이며 confidence는 Low이다. 보드 전력 실측이나 확정적인 에너지 효율 수치가 아니다.

최종 자원 사용률은 LUT 71.63%, FF 36.28%, BRAM 84.81%, DSP 85.42%이다. 100MHz에서 setup WNS는 +0.111ns, hold WHS는 +0.017ns로 timing을 만족한다. BRAM과 DSP가 모두 80%를 넘기 때문에 연산기를 더 추가하거나 buffer를 크게 만드는 방식은 배치와 배선 여유를 빠르게 줄인다. 따라서 이 결과는 정확도와 속도뿐 아니라 제한된 FPGA 안에서 전체 그래프가 실제로 배치·배선된 구현 결과로 해석해야 한다.
